### 4.3 时区修正

验证中发现并修复了一个会导致 **8 小时偏移** 的问题：

- PostgreSQL 的 `EXTRACT(EPOCH FROM timestamp without time zone)` 不读取会话 `TimeZone`
- 仅执行 `SET TIME ZONE 'Asia/Shanghai'` 后取 `EXTRACT(EPOCH FROM col)` 仍然把墙上时间当作 UTC
- 正确写法：`EXTRACT(EPOCH FROM (col AT TIME ZONE 'Asia/Shanghai')) * 1000`

修复后样例：

```text
PostgreSQL: 2026-10-20 12:34:56.789（上海墙上时间）
SQLite:     1792470896789
UTC:        2026-10-20T04:34:56.789Z
```

导入器现在还会主动拒绝 `timestamp with time zone` 列，避免静默二次偏移。

### 4.4 非空目标与 `--truncate`

- 目标已有数据且未加 `--truncate` → 明确报错，列出非空表
- 加 `--truncate` 后可重复导入，18 张表校验通过，数据未重复
- `--dry-run` 成功且未加 `--keep` → 自动删除临时库及 `-wal` / `-shm`

## 5. 在线备份与恢复

### 5.1 备份

```bash

BACKUP_DIR=/private/var/.../kirameku-p0-backups \
pnpm db:backup --prune
```

结果：

```text
size: 217088 bytes
sha256: 2d016b9117c9bee6ea7d644448052ad6529e700c6e32f11510b60cf3c69bd607
migration: 0000_initial.sql
integrity_check: ok
foreign_key_check: 0 violation(s)
```

生成的 `.meta.json` 记录文件名、时间、大小、SHA-256、迁移版本、完整性和外键检查结果。备份文件和 meta 文件权限为 `0600`，备份目录创建时使用 `0700`；验证后清理空的 `-wal` / `-shm` 边车文件。

### 5.2 恢复演练

1. 备份前写入 `p0_backup_test=before`
2. 备份后写入 `p0_after_backup=should-disappear`
3. 执行 `pnpm db:restore <backup> --target <db>`
4. 恢复后查询只剩 `p0_backup_test=before`
5. 旧的 DB / `-wal` / `-shm` 被重命名为 `.pre-restore-*` 保留
6. 恢复后 `integrity_check: ok`，`foreign_key_check` 无输出
7. SHA-256 与 `.meta.json` 一致
8. 篡改备份文件后恢复被拒绝：`checksum mismatch ...`，目标库未被覆盖
