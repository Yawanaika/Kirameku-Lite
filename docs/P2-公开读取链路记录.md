GitHub OAuth：

| 接口 | 实现 |
|:---|:---|
| `GET /api/auth/github/login` | 生成随机 `state`，写入 `kir_gh_state` HttpOnly Cookie，302 到 GitHub 授权页 |
| `GET /api/auth/github/callback` | 校验 `state`，用 `code` 换取 GitHub access token，读取 `/user`，按 `github_id` upsert `github_user`，签发本站 GitHub JWT，302 到 `${FRONTEND_ORIGIN}/auth/callback?token=...` |
| `GET /api/auth/github/me` | 读取 `Authorization: Bearer <github_token>`，返回当前 GitHub 用户 |

> GitHub 会话和管理员会话使用不同 JWT audience：管理员为 `aud=admin` + `kir_admin` Cookie，GitHub 访客为 `aud=github` + 前端 `localStorage.github_token`。两者不能互相冒用。GitHub token 默认 30 天有效；OAuth `state` Cookie 10 分钟有效，`Path=/api/auth/github`、`SameSite=Lax`、`HttpOnly`，生产环境带 `Secure`。

## 行为约定

- 公开 API 默认只返回 `published`，不会通过省略 `status` 暴露草稿；草稿查询参数会被校验拒绝。
- 文章详情 GET **不再自增浏览量**。详情页 SSR 和 prefetch 会放大计数，后续通过客户端上报 + 去重处理。
- 分类/标签的 `post_count` 不再依赖可能漂移的存储字段，而是按已发布文章实时聚合。
- 响应字段保持旧前端使用的 snake_case：`is_pinned`、`word_count`、`reading_time`、`published_at`、`post_count` 等。
- 文章/说说/评论/留言点赞是公开写接口，带只读模式检查和同源检查；点赞使用 `max(0, coalesce(likes, 0) + delta)` 原子更新，最低为 0。
- 评论、说说评论和留言创建必须携带有效 GitHub Bearer token；只允许评论已发布文章/说说，父评论/父留言必须存在、属于同一内容且为 `approved`。
- 评论/留言正文在服务端 `trim`，长度限制 1–5000 字；非法内容返回 422。
- 不存在的文章会渲染自定义 not-found 页面并输出 `noindex`。由于 Next 16 对动态页面采用流式响应，HTTP 状态可能是 200（soft 404）；这是 Next 已知行为，不是数据查询失败。
- 说说公开列表和计数固定为 `published`，草稿查询参数会被 422 拒绝。
- `chatter.images` 读取时安全 `JSON.parse`，非法或空值回退为 `[]`；说说评论创建成功后在数据库内原子增加 `comments_count`。
- `updated_at` 允许为 `null`，与旧接口保持一致。
- 留言公开读取只返回 `approved` 顶层留言；回复同样只返回 `approved`，并按创建时间升序递归组装。`rejected` 查询参数返回 422。
- 评论读取只返回 `approved`，并且只对 `published` 文章/说说生效；草稿内容即使有 approved 评论也不会暴露。评论树按创建时间倒序组装，父评论不在结果集中的 approved 回复会按旧逻辑成为根节点。
- 评论/留言点赞返回更新后的完整对象；评论对象带 `replies: []`，留言对象带当前 approved 回复树，兼容旧前端只读取 `likes` 的用法。
- GitHub OAuth 的 `state` Cookie 在回调后清除；回调失败返回 400，不会把无效 token 写到前端。GitHub 用户按 `github_id` upsert，GitHub 登录名/头像/bio 每次登录更新。
- GitHub token 和管理员 token 的 audience 分离；管理员接口只接受 `aud=admin` 且数据库中仍为管理员的会话。
- `/moments` 日期分组固定按 `Asia/Shanghai`，并使用 `Intl.DateTimeFormat.formatToParts` 拼接 `M月D日`；Node 的 `zh-CN` 数字月日格式会输出 `1/1`，不能直接使用。
- `/moments` 的 localStorage 状态在 hydration 后恢复；相对时间文本加 `suppressHydrationWarning`，避免服务端与客户端时间差导致警告。
- 友链公开读取只返回 `is_approved = 1` 的记录，并按 `sort`、`id` 升序；未审核友链不会出现在公开接口。
- 收藏夹按分类 `sort`、`id` 排序，站点按 `sort`、`id` 排序后分组；`platforms` 非 JSON 或非数组时回退为 `[]`，避免旧数据破坏页面。
- 站点配置沿用旧行为：能 `JSON.parse` 的值返回解析后的类型，否则返回原始字符串；因此 `cloud_music_playlist_id` 可能是数字，前端不能假定所有值都是字符串。
- 访客记录会解析 UA 为浏览器/系统/设备类型，并尝试 uapis.cn、ip-api.com 获取地理信息；本机/内网 IP 直接跳过。外部查询失败只记录空地理字段，不影响访问。
- 访客记录写入受 `SITE_READ_ONLY`、同源检查和 10 次/分钟/IP 限流保护；`/api/visitors/count` 已本地化，后台访客列表/删除仍回退旧服务。
- 小说模块已移除：`/novel/*`、`/reader3/*`、`/api/novel/*` 不再有路由，直接返回 404；导航、`/reader3` rewrite、`NOVEL_*` 环境变量和 Live2D 小说提示已清理。

## 数据现状

当前 `data/kirameku.db` 只有 schema、迁移记录和管理员数据：

```text
post=0, category=0, tag=0, post_tag=0
chatter=0, chatter_comment=0, comment=0
message=0, album=0, photo=0
github_user=0
friend_link=0, bookmark_category=0, bookmark_site=0
```
