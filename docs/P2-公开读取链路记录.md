# P2 公开读取链路记录

日期：2026-10-21

## 本轮完成

公开站点的文章读取链路已从旧 FastAPI 切到本地 SQLite：

| 接口 | 实现 |
|:---|:---|
| `GET /api/posts` | `app/api/posts/route.ts`，支持 `status`、`category`、`tag`、`page`、`size` |
| `GET /api/posts/count` | `app/api/posts/count/route.ts` |
| `GET /api/posts/[slug]` | `app/api/posts/[slug]/route.ts`，仅返回已发布文章 |
| `GET /api/posts/detail/[id]` | `app/api/posts/detail/[id]/route.ts`，仅返回已发布文章 |
| `POST /api/posts/[id]/like` | 本地点赞，保留 `{ likes }` 响应 |
| `POST /api/posts/[id]/unlike` | 本地取消点赞，保留 `{ likes }` 响应 |
| `GET /api/categories` | 本地分类列表，`post_count` 按已发布文章计算 |
| `GET /api/tags` | 本地标签列表，`post_count` 按已发布文章计算 |

说说读取链路：

| 接口 | 实现 |
|:---|:---|
| `GET /api/chatters` | `app/api/chatters/route.ts`，只返回已发布说说，支持 `page`、`size` |
| `GET /api/chatters/count` | `app/api/chatters/count/route.ts`，只统计已发布说说 |

留言读取链路：

| 接口 | 实现 |
|:---|:---|
| `GET /api/messages/list` | `app/api/messages/list/route.ts`，只返回 `approved` 顶层留言及嵌套回复，支持 `page`、`size` |
| `GET /api/messages/count` | `app/api/messages/count/route.ts`，只统计 `approved` 顶层留言 |

> `/api/messages/list` 是过渡路径。留言创建、点赞和后台管理仍由旧 FastAPI 处理；把本地 GET 放在 `/api/messages` 会抢走 POST 回退，因此等 GitHub OAuth 和留言写入迁移后再合并回 `/api/messages`。

相册读取链路：

| 接口 | 实现 |
|:---|:---|
| `GET /api/albums/list` | `app/api/albums/list/route.ts`，按 `sort`、`id` 升序返回相册 |
| `GET /api/albums/[id]/photos` | `app/api/albums/[id]/photos/route.ts`，按 `sort`、`id` 升序返回相册照片 |

> `/api/albums/list` 是过渡路径。相册创建/更新/删除和 `/api/albums/photos` 上传仍由旧 FastAPI 处理；本地只读路由不占用 `/api/albums` 和 `/api/albums/photos`，避免抢走旧写接口。

评论读取链路：

| 接口 | 实现 |
|:---|:---|
| `GET /api/comments/post/[postId]` | `app/api/comments/post/[postId]/route.ts`，只返回已发布文章的 approved 评论树 |
| `GET /api/chatters/[chatterId]/comments` | `app/api/chatters/[chatterId]/comments/route.ts`，只返回已发布说说的 approved 评论树 |

> 评论创建、点赞和后台管理仍由旧 FastAPI 处理。本地只读路由只匹配 `/post/:postId` 和 `/:chatterId/comments`，不会遮蔽 `/api/comments`、`/api/chatters/comments` 以及点赞路径。

友链、收藏夹、站点配置与访客：

| 接口 | 实现 |
|:---|:---|
| `GET /api/friend-links/list` | `app/api/friend-links/list/route.ts`，只返回已审核友链，按 `sort`、`id` 升序 |
| `GET /api/bookmarks` | `app/api/bookmarks/route.ts`，返回分类及其站点，`platforms` 安全解析为数组 |
| `GET /api/site-config/public` | `app/api/site-config/public/route.ts`，返回 key-value，值按旧逻辑尝试 `JSON.parse` |
| `GET /api/visitors/location` | `app/api/visitors/location/route.ts`，查询当前请求 IP 的地理信息；内网/本机 IP 直接返回 `{}` |
| `POST /api/visitors/record` | `app/api/visitors/record/route.ts`，本地记录访客，带只读模式、同源检查和 10 次/分钟/IP 限流 |
| `GET /api/visitors/count` | `app/api/visitors/count/route.ts`，返回访客总数 |

> `/api/friend-links/list` 是过渡路径。友链创建/更新/删除和 `/api/friend-links/admin` 仍由旧 FastAPI 处理；本地 GET 不占用 `/api/friend-links`，避免抢走旧写接口。`/api/site-config/public` 同理，站点配置写接口仍回退旧服务。收藏夹的 `/api/bookmarks/categories`、`/api/bookmarks/sites` 管理路径也继续回退。

服务层：

- `server/modules/posts/service.ts`：列表、详情、按 ID 查询、计数、点赞/取消点赞。
- `server/modules/categories/service.ts`：分类及已发布文章计数。
- `server/modules/tags/service.ts`：标签及已发布文章计数。
- `server/modules/chatters/service.ts`：说说列表、按 ID 查询和计数。
- `server/modules/messages/service.ts`：已审核留言的顶层分页、嵌套回复树和计数。
- `server/modules/albums/service.ts`：相册列表和按相册读取照片。
- `server/modules/comments/service.ts`：已发布文章/说说的 approved 评论树。
- `server/modules/friend-links/service.ts`：已审核友链列表。
- `server/modules/bookmarks/service.ts`：收藏夹分类/站点聚合与 `platforms` JSON 解析。
- `server/modules/site-config/service.ts`：公开 key-value 配置及 JSON 值解析。
- `server/modules/visitors/service.ts`：访客记录、列表、计数、UA 解析、IP 地理信息与运营商中文名。
- `server/modules/site-stats/service.ts`：首页文章/说说/照片数量。

页面与 Feed：

- `/posts` 首屏改为服务端读取；分类筛选和加载更多仍在客户端完成。
- `/posts/[slug]` 首屏改为服务端读取，并增加 `generateMetadata`、404 页面；点赞、代码高亮、灯箱、目录和评论仍在客户端运行。
- 首页统计不再请求旧 FastAPI，直接查 SQLite。

- 留言列表和计数改读本地 SQLite：前端 `getMessages` 使用 `/api/messages/list`，`getMessagesCount` 使用本地 `/api/messages/count`；留言创建、点赞和后台管理仍回退旧服务。
- 相册列表和照片改读本地 SQLite：前端 `getAlbums` 使用 `/api/albums/list`，`getAlbumPhotos` 使用本地 `/api/albums/[id]/photos`；相册写接口和照片上传仍回退旧服务。
- 文章评论和说说评论改读本地 SQLite：`getPostComments` 使用 `/api/comments/post/[postId]`，`getChatterComments` 使用 `/api/chatters/[chatterId]/comments`；评论创建、点赞和后台管理仍回退旧服务。
- 友链和收藏夹改读本地 SQLite：`getFriendLinks` 使用 `/api/friend-links/list`，`getBookmarks` 使用 `/api/bookmarks`；页面仍是客户端渲染，首屏后加载数据。
- 音乐播放器的站点配置改读本地 `/api/site-config/public`，歌单仍由本地 `/api/music` 通过 `@meting/core` 拉取。
- 访客追踪改为本地 `/api/visitors/record` 和 `/api/visitors/location`；内网 IP 不请求外部地理接口，记录写入失败不会阻塞页面。
- `/feed` 改为本地文章列表 + 详情，不再请求 `127.0.0.1:8000`。
- `PostCard` 与详情页日期固定按 `Asia/Shanghai` 格式化，并处理 SSR 文本差异。

- `BackgroundProvider` 不再在挂载前返回 `null`；`(site)` 下页面现在会输出真实 SSR HTML。此前该早退会让整棵站点树在服务端为空壳。
- `/messages` 为 `useSearchParams` 增加 Suspense 边界；`/garden` 的 localStorage 门禁改到挂载后执行，避免服务端误判未解锁并 307。

## 行为约定

- 公开 API 默认只返回 `published`，不会通过省略 `status` 暴露草稿；草稿查询参数会被校验拒绝。
- 文章详情 GET **不再自增浏览量**。详情页 SSR 和 prefetch 会放大计数，后续通过客户端上报 + 去重处理。
- 分类/标签的 `post_count` 不再依赖可能漂移的存储字段，而是按已发布文章实时聚合。
- 响应字段保持旧前端使用的 snake_case：`is_pinned`、`word_count`、`reading_time`、`published_at`、`post_count` 等。
- 点赞是公开写接口，但增加了只读模式检查和同源检查；限流/去重留到 P2 写入链路。
- 不存在的文章会渲染自定义 not-found 页面并输出 `noindex`。由于 Next 16 对动态页面采用流式响应，HTTP 状态可能是 200（soft 404）；这是 Next 已知行为，不是数据查询失败。
- 说说公开列表和计数固定为 `published`，草稿查询参数会被 422 拒绝。
- `chatter.images` 读取时安全 `JSON.parse`，非法或空值回退为 `[]`；`comments_count` 暂时继续使用存储字段，因为评论写入仍在旧服务。
- `updated_at` 允许为 `null`，与旧接口保持一致。
- 留言公开读取只返回 `approved` 顶层留言；回复同样只返回 `approved`，并按创建时间升序递归组装。`rejected` 查询参数返回 422。
- 留言本地路由使用 `/api/messages/list`，避免 `/api/messages` 的 POST/点赞请求被本地 GET handler 截断；旧 FastAPI 的写接口仍可用。
- 相册列表按 `sort`、`id` 升序；照片按 `sort`、`id` 升序，并且只返回指定相册的照片。非法相册 id 返回 422，空相册返回 `[]`。
- 相册本地只读路由使用 `/api/albums/list`，不占用旧写接口 `/api/albums` 和 `/api/albums/photos`。
- 评论读取只返回 `approved`，并且只对 `published` 文章/说说生效；草稿内容即使有 approved 评论也不会暴露。评论树按创建时间倒序组装，父评论不在结果集中的 approved 回复会按旧逻辑成为根节点。
- 评论本地只读路由只匹配 `/api/comments/post/:postId` 和 `/api/chatters/:chatterId/comments`，不会遮蔽评论创建、点赞和后台管理路径。
- `/moments` 日期分组固定按 `Asia/Shanghai`，并使用 `Intl.DateTimeFormat.formatToParts` 拼接 `M月D日`；Node 的 `zh-CN` 数字月日格式会输出 `1/1`，不能直接使用。
- `/moments` 的 localStorage 状态在 hydration 后恢复；相对时间文本加 `suppressHydrationWarning`，避免服务端与客户端时间差导致警告。
- 暂不新增本地 `/api/chatters/[id]` 动态路由：它会遮蔽仍需回退到旧服务的 `/api/chatters/comments`、`/api/chatters/admin` 等路径。迁移评论前先补静态子路由。
- 友链公开读取只返回 `is_approved = 1` 的记录，并按 `sort`、`id` 升序；未审核友链不会出现在公开接口。
- 收藏夹按分类 `sort`、`id` 排序，站点按 `sort`、`id` 排序后分组；`platforms` 非 JSON 或非数组时回退为 `[]`，避免旧数据破坏页面。
- 站点配置沿用旧行为：能 `JSON.parse` 的值返回解析后的类型，否则返回原始字符串；因此 `cloud_music_playlist_id` 可能是数字，前端不能假定所有值都是字符串。
- 访客记录会解析 UA 为浏览器/系统/设备类型，并尝试 uapis.cn、ip-api.com 获取地理信息；本机/内网 IP 直接跳过。外部查询失败只记录空地理字段，不影响访问。
- 访客记录写入受 `SITE_READ_ONLY`、同源检查和 10 次/分钟/IP 限流保护；`/api/visitors/count` 已本地化，后台访客列表/删除仍回退旧服务。
- 小说模块已移除：`/novel/*`、`/reader3/*`、`/api/novel/*` 不再有路由，直接返回 404；导航、`/reader3` rewrite、`NOVEL_*` 环境变量和 Live2D 小说提示已清理。

## 数据现状

当前 `data/kirameku.db` 只有 schema、迁移记录和管理员数据：

```text
post=0, category=0, tag=0, post_tag=0
chatter=0, chatter_comment=0, comment=0
message=0, album=0, photo=0
friend_link=0, bookmark_category=0, bookmark_site=0
site_config=0, visitor=0
```

因此页面会显示空状态，这是数据为空而不是接口失败。文章/说说/留言/相册/评论/友链/收藏夹/站点配置/访客服务测试使用临时 SQLite 数据库和固定 fixture，覆盖分页、草稿/审核隔离、JSON 解析、嵌套回复、排序和访客记录等行为。
